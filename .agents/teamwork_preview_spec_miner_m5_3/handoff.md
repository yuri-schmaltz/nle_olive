## 2. Logic Chain

1. **Manifest Identification**:
   - The desktop file, appdata metainfo, and icon names across the Olive repository consistently use the reverse-DNS ID `org.olivevideoeditor.Olive`.
   - The primary binary generated by `app/CMakeLists.txt` is installed to `${CMAKE_INSTALL_PREFIX}/bin/olive-editor`.
   - Therefore, the top-level identification keys are:
     `"app-id": "org.olivevideoeditor.Olive"` and `"command": "olive-editor"`.

2. **Runtime & SDK Selection**:
   - Olive modernization requires pure Qt6 (`BUILD_QT6=ON`).
   - The KDE Application Runtime (`org.kde.Platform` / `org.kde.Sdk`) provides Qt6 base libraries, Wayland/XCB platform plugins, Mesa graphics drivers, and modern desktop style integrations.
   - Runtime version `6.8` (KDE 6.8+) is the targeted standard LTS branch.

3. **Sandboxing Permissions (`finish-args`)**:
   - Non-linear video editors perform GPU compositing, audio mixing, file input/output, and user notification.
   - `--share=ipc`: Required for MIT-SHM shared memory X11 communication.
   - `--socket=x11` & `--socket=wayland`: Ensures Olive runs natively on Wayland compositors (KWin, Mutter) with seamless fallback to X11.
   - `--socket=pulseaudio`: Required for real-time audio playback via PortAudio and PipeWire/PulseAudio daemons.
   - `--device=dri`: Grants access to `/dev/dri/*` hardware acceleration nodes for OpenGL timeline preview and GLSL shader processing.
   - `--filesystem=host`: Essential for an NLE to import raw media from user disks, camera cards, and network shares, and to export render output.
   - `--talk-name=org.freedesktop.Notifications`: Enables background export completion notifications via the desktop environment notification bus.

4. **Module Dependency Topology**:
   - PortAudio has no dependencies on OpenEXR or OCIO; it can build first via `autotools`.
   - OpenEXR v3.2+ strictly depends on Imath v3.1+. Therefore, `imath` must build immediately before `openexr`.
   - OpenImageIO v2.5+ uses OpenEXR and OpenColorIO. Therefore, `imath`, `openexr`, and `opencolorio` must be built before `openimageio`.
   - Olive Video Editor consumes all five libraries (`PortAudio`, `Imath`, `OpenEXR`, `OpenColorIO`, `OpenImageIO`) along with the runtime's Qt6 and FFmpeg. Thus, `olive` is the terminal module.
   - Test/app/python features in OCIO (`-DOCIO_BUILD_APPS=OFF`, `-DOCIO_BUILD_PYTHON=OFF`, `-DOCIO_BUILD_TESTS=OFF`, `-DOCIO_BUILD_GPU_TESTS=OFF`) and OIIO (`-DOIIO_BUILD_TESTS=OFF`, `-DOIIO_BUILD_TOOLS=OFF`, `-DUSE_PYTHON=OFF`) are disabled to ensure compact build sizes, fast build times, and zero unnecessary python dependencies.

5. **Filesystem Cleanup**:
   - Intermediate development headers (`/include`), pkg-config files (`/lib/pkgconfig`), and manual pages (`/share/man`) are only needed while compiling subsequent modules in the sandbox.
   - Adding them to the top-level `"cleanup"` array ensures they are stripped from the exported Flatpak artifact.

## 3. Caveats

1. **Network Sandbox & Offline Builds**:
   - When building in an isolated environment without network access (e.g., standard Flatpak builder or Flathub build workers), source tarballs must be cached or mirrored locally. The SHA256 checksums specified in the manifest guarantee cryptographic integrity.
2. **Relative Source Path**:
   - The Olive module uses `"type": "dir", "path": "../.."`. This requires that the manifest resides in `packaging/flatpak/` relative to the git repository root. If invoked from another directory, `flatpak-builder` resolves relative to the manifest file's directory.
3. **OpenTimelineIO (OTIO)**:
   - OTIO is an optional dependency in Olive (`find_package(OpenTimelineIO)`). In accordance with the dispatch specification, it is not bundled in this baseline manifest; native FCP7 XML interchange functions independently in pure Qt6 without OTIO.
